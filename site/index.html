DadBox

Two buttons. One voice.
No screen, no phone, no account.

A die-cast aluminium box for a child, an iPhone app for the parent who lives somewhere else. The child presses Record, talks, presses again — and the parent hears it. When a message comes back, Play glows. That's the whole interface.

▶ Start building ⌥ Source on GitHub
SECTION 01

What it is

A phone call needs both people free at the same moment — and a kid on a video call with a parent they miss often just goes quiet. A box that holds a voice until someone is ready to hear it fits how a child actually stays close to someone who isn't there.

The child · age 6–9

The box

  1. Press Record. It turns steady red — and only now is the microphone powered.
  2. Talk. Up to five minutes. No timer, nothing to read.
  3. Press Record again. One green pulse means got it: the message is safely on disk.
  4. When the parent answers, Play breathes green and the box chimes once (never during quiet hours). Press it to listen.
Record steady dim blue — ready Record slow blue blink — not ready (the app explains why) Record steady red — recording, mic on Play breathing green — a message waits
The parent

The iPhone app

Two screens, and it should be hard to add a third:

Conversation — one timeline, both directions, the whole archive. Tap to record, tap to stop, review, send. Each message you sent says sent → on the box → played 19:12, because "did it arrive?" is the question you'll actually have.

Box — signal, last check-in, queue, quiet hours, volume, and any fault in words. The child never has to interpret an error; the adult reads it here.

A push notification arrives when the child sends something — and, just as important, when the box hasn't checked in for hours.

The rules that shaped every decision

A six-year-old can use it aloneTwo buttons, both obvious. No menus, no pairing, no "are you sure?"
No red light, no microphoneThe mic's power comes from the same pin that lights Record red — by wiring, not by software promise. Everyone in the room can see when it listens.
Nothing recorded is ever lostAudio hits the SD card while the child is still talking. The outbox is never emptied until the server confirms a durable, checksummed copy.
It never needs the other house's Wi-FiThe box travels between two homes, so it carries its own LTE connection. No passwords, no router to depend on.
A child's voice is the most sensitive data hereEnd-to-end encrypted (AES-256-GCM). The server stores ciphertext it cannot play. No transcription, no speech services, no analytics.
It lives in a school bagPresses shorter than 0.5 s are ignored; holding both buttons for 3 s sets a travel lock that survives a reboot.
SECTION 02

How it works

Three pieces that all speak one written protocol (docs/PROTOCOL.md). The protocol changes first; the box, server and app follow.

Recording

16 kHz mono from the I2S mic, written to /data as it happens. On stop: trim silence, encode to Opus at 16 kbps (~120 KB a minute), encrypt, append a CRC, fsync, rename into the outbox. Only then the green pulse.

Sending

Resumable upload in 32 KB chunks over LTE. No link? It waits, forever, and the child never hears about a network. A 3-minute message went from queued to delivered in 8.5 s on a CHF 6/month SIM.

Receiving

Plugged in, the box checks in every minute (plus a realtime "doorbell" for instant delivery). It downloads, stores, and lights Play. Oldest first, one per press; with nothing new, Play repeats the last message.

The box is a Linux machine

Raspberry Pi OS Lite with a read-only root: only the /data partition is ever written, so pulling the plug is safe — tested idle, mid-boot and mid-recording. A hardware watchdog restarts a hung service. You can ssh into it from anywhere over Tailscale and drive it with dadboxctl.

The code runs on your laptop too

The state machine is pure Python with no hardware imports. The same service runs on a Mac as a simulator with a web UI — virtual buttons, lights and speaker — against a fake or the real server. You can try the whole system before buying a single part.

SECTION 03

Where it stands

Honest status as of 2 October 2026: a working bench prototype, not a finished product. You'd be building alongside us, not after us — the repo's docs/BUILD-LOG.md has every session, failures included.

Working

  • Server live on Supabase; every protocol endpoint exercised end-to-end with a fake box (dropped-link resume, shuffled chunks, "box is late" alert)
  • Box software: 70 tests, simulator, deployed to the Pi
  • LTE: modem as a network interface; 3-minute message delivered in 8.5 s
  • Read-only root; four pulled plugs, zero files lost
  • Both buttons and all six light channels wired and verified
  • 5 V in on the header pins; no undervoltage
  • iOS app: conversation, recorder, Box screen; 31 tests on the protocol library

Not yet

  • Speaker crackles: the spare amp board was likely damaged when its ground wire landed on GAIN. A new amp is next.
  • The microphone hasn't recorded on the real hardware yet
  • Modem power key (GPIO 4) unproven
  • Push notifications wait for an Apple APNs key
  • Enclosure not drilled; the layout and 1:1 drill templates are ready
  • Battery deferred: the first box is mains-only (pull the plug to turn it off)

Outside Switzerland?

Everything is generic except the SIM. Pick any data SIM whose network the SIM7670G supports (it covers the common European LTE bands, including 20 and 28) and set its APN.

SECTION 07

Lessons from the bench

Things that cost us an evening each, so they don't cost you one.

USB-C couplers work one way up

A socket-to-socket panel coupler powered the box with the plug one way and stayed dark the other. A USB-C supply only switches on after seeing the CC resistor, and a coupler passes the plug's single CC wire to only one of two pins. Use a socket with a cable tail.

A wire on GAIN killed an amp

The amp's ground wire landed on the neighbouring GAIN pin. Moving it fixed the pitch, but the board kept scratching even on pure digital silence — damage, not signal. Check every ground before power; buy a spare amp.

overlayroot puts /data in RAM

The stock read-only overlay also overlays every mount under /. Without recurse=0 your "safe" partition silently lives in memory.

The modem isn't who it says

The SIM7670G enumerates as Qualcomm 05c6:9330. At DIALMODE=1 it registers and gets an address but forwards nothing; 0 fixes it, and the setting persists.

Re-flashing reused a sequence number

A fresh card restarted message numbering at 1; the server refused it as a duplicate and the stuck upload blocked check-ins. Now the server tells the box its highest number, and one bad message never blocks the rest.

Hold the power key down at boot

GPIO 4 floats high at boot, and a power key held 2.5 s switches the modem off. gpio=4=op,dl in config.txt holds it low from the first second.
